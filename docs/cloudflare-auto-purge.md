# อัปเดตราคาหน้าร้านอัตโนมัติ

## สำหรับผู้ดูแลร้าน

เมื่อบันทึกราคาผ่าน SoundDD ระบบสามารถแจ้ง Cloudflare ให้ล้างข้อมูลหน้าร้านที่อาจยังแสดงราคาเดิมได้ รวมถึงช่วงที่โปรเริ่มและหมดเวลา

หลังบันทึกราคา ระบบจะแสดงสถานะระหว่างทำงาน หาก Cloudflare ขัดข้อง ระบบจะเก็บรายการไว้เพื่อลองใหม่ การลองใหม่จะไม่เปลี่ยนราคาสินค้าอีกครั้ง

### ความหมายของสถานะ

| สถานะ | หมายความว่า |
|---|---|
| บันทึกแล้ว · กำลังอัปเดตหน้าร้าน | ราคาใหม่ถูกบันทึกแล้ว ระบบกำลังจัดการหน้าร้าน |
| ส่งคำขออัปเดตหน้าร้านแล้ว | Cloudflare รับคำขอล้างข้อมูลแล้ว ยังไม่ใช่การตรวจยืนยันทุกหน้าว่าแสดงราคาใหม่ |
| อัปเดตหน้าร้านล่าช้า · ระบบจะลองใหม่ | ระบบกำลังรอลองอีกครั้ง ราคาที่บันทึกไว้ยังอยู่ |
| บันทึกแล้ว · การอัปเดตหน้าร้านต้องตรวจสอบ | ผู้ดูแลควรตรวจการเชื่อมต่อ แล้วกดลองใหม่ได้ |
| ทดลองอัปเดตหน้าร้านแล้ว · ยังไม่ส่ง Cloudflare | ตรวจการทำงานภายในแล้ว แต่ยังไม่ได้ล้างข้อมูลบนเว็บจริง |

### เริ่มหรือพักการทำงาน

ผู้ใช้ทั่วไปใช้สวิตช์ **เปิดอัปเดตราคาหน้าร้านอัตโนมัติ** เพียงอันเดียว เมื่อเปิด ระบบจะรับรายการใหม่และทำรายการที่ค้างต่อ เมื่อพักระบบ รายการเดิมยังอยู่

โดยปกติไม่ต้องเปิด **ตัวเลือกเพิ่มเติม** รายการในนั้นเป็นค่าประจำเว็บไซต์ ใช้เมื่อมีหน้าโปรหรือหน้าอื่นที่แสดงราคาเพิ่มเติม

หากหน้า Settings ระบุ **โหมดทดลอง** หมายถึงเปิดสวิตช์แล้วแต่ระบบยังไม่ได้ล้างข้อมูลบนเว็บจริง ผู้ดูแลระบบต้องตั้งค่าการเชื่อมต่อและทดสอบบนเว็บทดลองก่อน

ระบบเริ่มต้นโดยปิดการอัปเดตอัตโนมัติและเปิดโหมดทดลองไว้ การเปิดใช้งานเว็บจริงต้องให้ผู้ดูแลระบบตั้งค่าการเชื่อมต่อบนเซิร์ฟเวอร์และทดสอบบนเว็บทดลองก่อน

หน้าที่รองรับในรุ่นนี้คือหน้าสินค้า หน้าหมวดหมู่ หน้ารวมสินค้า หน้ารวมแบรนด์ และ URL สาธารณะที่ผู้ดูแลเพิ่มเอง เว็บที่มีตัวกรองหรือหน้าพิเศษซึ่งแสดงราคาต้องตรวจและเพิ่ม URL เหล่านั้นก่อน

การเปลี่ยนราคาจากหน้า WooCommerce โดยตรง ไฟล์นำเข้า หรือระบบอื่นยังใช้การล้างแคชเดิมของเว็บไซต์ การอัปเดตนี้ครอบคลุมการเปลี่ยนราคาผ่าน SoundDD เท่านั้น

## สำหรับผู้ดูแลระบบเว็บไซต์

### ก่อนเปิดส่งคำขอจริง

ตรวจบนเว็บทดลองก่อนว่า Cloudflare เก็บหน้าใด แยกแคชตามอุปกรณ์หรือเงื่อนไขอื่นอย่างไร และปลั๊กอิน Cloudflare ที่มีอยู่ล้างหน้าเดิมหรือไม่ ตรวจราคาใน WooCommerce เทียบกับหน้าร้านแบบไม่ล็อกอิน รวมหน้าสินค้า หน้ารวมสินค้า และมือถือ

หากมีหน้าพิเศษหรือตัวกรองที่แสดงราคา ให้ตรวจ URL เหล่านั้นก่อนเปิดส่งคำขอจริง

Cloudflare รับคำขอแล้วไม่ได้ยืนยันว่าทุกหน้าหรือทุกอุปกรณ์แสดงราคาใหม่ รุ่นนี้ยังไม่มีขั้นตอนเปิดหน้าร้านไปตรวจราคาแทนผู้ดูแล

### ตั้งค่าการเชื่อมต่อในปลั๊กอิน

1. เปิด **ตั้งค่า → การอัปเดตราคาหน้าร้าน → การเชื่อมต่อ Cloudflare** ด้วยบัญชีผู้ดูแลระบบ
2. กรอก **Zone ID** ของเว็บไซต์ และ **API Token** ที่มีสิทธิ์ Cache Purge เฉพาะเว็บไซต์นั้น
3. กด **ตรวจการเชื่อมต่อและบันทึก** ระบบจะลองล้าง URL ทดสอบที่ไม่มีหน้าสินค้า เพื่อเช็กสิทธิ์โดยไม่ล้างหน้าร้านทั้งเว็บ
4. เปิดสวิตช์อัปเดตอัตโนมัติ และบันทึกการตั้งค่า
5. ทดลองกับสินค้าหนึ่งตัว เมื่อพร้อมส่งคำขอล้างข้อมูลจริงให้เอาเครื่องหมาย **ทดลองระบบโดยยังไม่อัปเดตเว็บไซต์จริง** ออก แล้วบันทึก

ไม่ต้องแก้ `wp-config.php` หรือตั้งค่า environment สำหรับการเชื่อมต่อใหม่ผ่านหน้าปลั๊กอิน Token ถูกเข้ารหัสก่อนเก็บในฐานข้อมูลและไม่ส่งกลับมาแสดง กรอก Token ว่างไว้เมื่อต้องการตรวจการเชื่อมต่อเดิมซ้ำ

การตรวจเชื่อมต่อยืนยันว่า API รับคำขอล้างแคชได้ แต่ยังต้องทดลองสินค้าเพื่อยืนยันว่าหน้าร้านแสดงราคาใหม่จริง

### จำนวนหน้าและอุปกรณ์จัดการอัตโนมัติ

ไม่มีช่องจำนวนสินค้าต่อหน้าหรือช่องเลือกอุปกรณ์ ระบบใช้การล้างตามเส้นทางสินค้าหรือหมวดหมู่ เพื่อครอบคลุมหน้าถัดไปและรูปแบบแคชทั้งหมดใต้เส้นทางนั้น หน้าแรกจะล้างเฉพาะ URL พร้อมแคชแบบทั่วไป คอมพิวเตอร์ มือถือ และแท็บเล็ต เพื่อไม่ให้ล้างทั้งเว็บไซต์

เว็บที่ใช้ลิงก์แบบเก่าผ่าน query จะใช้ URL แบบเจาะจงและแบ่งงานตามจำนวนสินค้าทั้งเว็บเป็นขอบเขตบน อาจมีงานมากกว่าเว็บที่ใช้ลิงก์ปกติ งานเกินขอบเขตที่รองรับจะแจ้งให้ตรวจสอบ

หน้าแรกถูกเพิ่มให้อัตโนมัติ ส่วนหน้าโปรหรือหน้าอื่นที่แสดงราคาและมีแคช สามารถใส่ URL เพิ่มได้ เมนูนี้เป็นตัวเลือก ไม่จำเป็นสำหรับหน้าสินค้าและหมวดหมู่มาตรฐาน

### แก้ปัญหาเบื้องต้น

- **รายการรออยู่นาน**: ตรวจว่าระบบงานเบื้องหลังของ WordPress ทำงาน แล้วเปิดการส่งรายการ
- **ต้องตรวจสอบ**: ตรวจการเชื่อมต่อหรือการตั้งค่าสิทธิ์ Cloudflare จากนั้นใช้ปุ่มลองอัปเดตหน้าร้านใหม่
- **ราคาใน WooCommerce ยังไม่เปลี่ยน**: ตรวจผลบันทึกราคาก่อน การล้างแคชไม่สามารถแก้การบันทึกที่ไม่สำเร็จได้
- **หน้าสินค้าถูก แต่หน้าหมวดหมู่ยังเก่า**: ตรวจ URL หน้ารวมสินค้าที่ถูกล้าง และตรวจว่ามีแคชอื่นบนเซิร์ฟเวอร์หรือไม่

การพักการส่งจะเก็บรายการเดิมไว้ การหยุดเก็บรายการจะมีผลกับการเปลี่ยนราคาครั้งใหม่ แต่ไม่ลบรายการที่รออยู่

## รายละเอียดทางเทคนิค

ส่วนนี้สำหรับนักพัฒนา ดูเพิ่มเติมที่ [แผนพัฒนา](cloudflare-auto-purge-plan.md)

- ตาราง `sdd_cache_outbox` และ `sdd_cache_targets` แยกจาก core schema รุ่น 5; ค่าเริ่มต้น capture/dispatch ปิด
- outbox เขียนพร้อมราคาและประวัติใน transaction เดียวกัน; การส่ง HTTP เกิดหลัง COMMIT
- เมื่อเก็บรายการไม่สำเร็จ การบันทึกราคานั้นจะถูก rollback เพื่อไม่ให้ราคาเปลี่ยนโดยไม่มีงานอัปเดตหน้าร้าน
- Action Scheduler ประมวลผล และ WP-Cron recovery ช่วยปลุกงานที่ยังค้าง
- ใช้ purge by prefix สำหรับเส้นทางที่ปลอดภัย ครอบคลุม pagination และ cache-key variants; ไม่ใช้ prefix ที่เป็นรากเว็บไซต์
- Root/query URLs ใช้ exact URL พร้อม no-header และ `CF-Device-Type` ทั้งสามค่า; custom keys อื่นบน root/query URLs ยังต้องตรวจแยก
- รวมเป้าหมายไม่เกิน 100 ต่อรอบ แยก API requests สำหรับ files/prefixes; หากส่วนใดล้มเหลว retry ทั้ง batch ได้โดยไม่เปลี่ยนราคา เคารพ `Retry-After` สำหรับ 429
- Connection API ใช้ `manage_options`, cookie + nonce; token ใช้ AES-256-GCM กับคีย์จาก WordPress auth salt เก็บ option แบบไม่ autoload; เมื่อเปลี่ยน salts ต้องกรอก token ใหม่
- ยังไม่รองรับการค้นหา dependency ของ shortcode/widget และ query filter ที่ถูก cache โดยอัตโนมัติ
- `accepted` แปลว่า Cloudflare รับคำขอแล้ว ไม่ได้ตรวจ HTML ราคาปลายทาง
- การปิด/เปิดปลั๊กอินเก็บคิวไว้; งานที่ยังไม่สำเร็จไม่ถูกลบตามอายุ

### ทดสอบใน Local

ทดสอบ Auto Purge 46 checks, regression เดิม และ JavaScript รวม 91 checks ผ่านบน Local โดยจำลองคำตอบ HTTP ไม่ได้ส่งคำขอไป Cloudflare จริง ภาพหน้าจอเป็น fixture จาก component ปัจจุบันที่ [ดูได้ที่นี่](screenshots/development/cloudflare-settings-fixture.png) ผลนี้ยังไม่ยืนยันการทำงานบน staging หรือ Prod

### ผลตรวจการตั้งค่าแบบใหม่

ชุดทดสอบคิวและการเชื่อมต่อผ่าน 54 checks รวมการล้างเส้นทางแทนการนับหน้า, การเก็บ Token แบบเข้ารหัส, การตรวจซ้ำโดยไม่กรอกรหัสเดิม และการป้องกันค่าการเชื่อมต่อเดิมเมื่อทดสอบไม่ผ่าน JavaScript ผ่าน session 12 scenarios และ UI 15 tests

การทดสอบนี้ใช้คำตอบ Cloudflare จำลอง ยังต้องยืนยันผลกับ cache rules และหน้าร้านจริงก่อนเปิด Prod อ้างอิงวิธีล้างเส้นทางจาก [Cloudflare: purge by prefix](https://developers.cloudflare.com/cache/how-to/purge-cache/purge_by_prefix/)

### ค้นหาหน้าแสดงสินค้าอัตโนมัติ

ระบบค้นหาเนื้อหาสาธารณะที่เผยแพร่และไม่ตั้งรหัสผ่าน รองรับ shortcode สินค้าของ WooCommerce/Flatsome, บล็อกสินค้าของ WooCommerce และวิดเจ็ตสินค้าของ Elementor ไม่ต้องกรอก URL ของหน้าที่ตรวจพบ รายการอยู่ใต้การเชื่อมต่อ Cloudflare และรีเฟรชหลังแก้ไขเนื้อหาหรือภายในหนึ่งชั่วโมง

หน้าที่ระบุรหัสสินค้าชัดเจนผ่าน shortcode ของ WooCommerce จะล้างเฉพาะเมื่อสินค้านั้นเปลี่ยน ส่วนหน้ารวมสินค้าที่เปลี่ยนตามเงื่อนไขยังล้างร่วมกับการบันทึกทุกครั้ง งานเบื้องหลังรวม URL ซ้ำในรอบเดียวกัน ระบบอ่านเนื้อหาโดยไม่เปิดรัน shortcode หรือเรียกหน้าเว็บระหว่างบันทึกราคา เตรียมรายการก่อนเริ่มธุรกรรมราคา

หน้าอ้างอิงบล็อกที่ใช้ซ้ำหรือ UX Block จะรวมไว้เพื่อความครอบคลุม แม้บางหน้าจะไม่มีสินค้า ระบบเฉพาะของธีมหรือปลั๊กอินอื่นอาจตรวจไม่พบ จึงยังมีช่องเพิ่มหน้าพิเศษแบบพับเก็บไว้ ราคาที่พิมพ์ลงข้อความหรือรูปภาพเองจะไม่เปลี่ยนจากการล้างแคช

### ก่อนเปิดบนเว็บไซต์จริง

1. สำรองฐานข้อมูลและเก็บ ZIP รุ่นที่ใช้อยู่ ทดลองกู้คืนบน Staging และใช้รุ่นที่มีเลขเวอร์ชันสูงกว่ารุ่นติดตั้งเมื่อเผยแพร่ Release
2. ใช้โหมดทดลองบน Staging ก่อน ทดสอบแก้ราคาแบบทีละรายการ แบบหลายรายการ สินค้าแบบตัวเลือก และโปรที่เริ่มและคืนราคาอัตโนมัติ ตรวจว่าคิวจบและครอบคลุมหน้าสินค้า หมวดหมู่ และหน้าโปร
3. ตั้งค่า Token เฉพาะโดเมนจริง เปิดส่งคำขอ Cloudflare แล้วทดลองสินค้าหนึ่งตัว ตรวจราคาหน้าร้านจากหน้าต่างไม่ระบุตัวตนทั้งมือถือและเดสก์ท็อป สถานะ Cloudflare รับคำขอแล้วบอกเพียงว่า API ตอบรับ
4. ตรวจอายุรายการค้างและสถานะต้องตรวจสอบหลังงาน Bulk หากต้องพักการส่ง ให้ใช้สวิตช์อัปเดตราคาหน้าร้าน การหยุดแก้ไขทั้งร้านจะหยุดงานเริ่มและคืนราคาโปรด้วย
5. ให้ผู้ดูแลเว็บไซต์เป็นผู้เปลี่ยนการตั้งค่าแบรนด์และสวิตช์เปิดหรือหยุดการแก้ไข จำกัดผู้เผยแพร่ GitHub Release และตรวจ ZIP ที่จะติดตั้ง ตัวอัปเดตยังอาศัยความน่าเชื่อถือของ GitHub Release
