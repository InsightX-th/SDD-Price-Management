# SoundDD Stock & Price — P5 release-readiness — test build 0.5.11

## 0.5.21 — จัดกึ่งกลางลูกศรสรุปราคา

กำหนดช่องลูกศรแยกจากช่องราคาเพื่อจัดกึ่งกลางระหว่างแต่ละช่วง และปิด pseudo-element จากรูปแบบเดิมที่อาจทับตำแหน่งลูกศร พร้อมเพิ่ม asset version เพื่อให้เบราว์เซอร์โหลด CSS/JS ล่าสุด

ปลั๊กอินนี้พัฒนาสำหรับร้าน production โดยใช้ Local ที่ติดตั้งสำเนาข้อมูลสำรองจริงเป็นสภาพแวดล้อมทดสอบ รุ่น 0.5.11 นี้เป็น test build สำหรับ Local ไม่ใช่ขั้นตอน deploy production; ให้ปิด production runtime/security/restore/load gates ก่อนนำขึ้น production

## ติดตั้ง

1. ตรวจว่า Local ใช้สำเนา backup ที่ต้องการทดสอบ แล้วไป WordPress → Plugins → Add New → Upload Plugin เลือก ZIP `sdd-stock-price-0.5.11-local-test.zip` และ Activate
2. Login ด้วย administrator แล้วเปิดเมนู **สต็อก & ราคา** → **ตั้งค่า**
3. เลือกเฉพาะ product_tag ที่เป็นแบรนด์จริง ไม่เลือกแท็กอื่น ไม่มีการย้าย/ลบแท็ก
4. อ่านเงื่อนไขการใช้งานแล้วกด **เปิดการบันทึก** เพื่อบันทึกแบรนด์ที่เลือกและเปิด writer; หากต้องการหยุดภายหลัง ให้ติ๊ก **หยุดการบันทึก** และบันทึกการตั้งค่า
5. เริ่มตรวจราคาปกติ/ราคาโปร/สถานะกับ simple product ที่ไม่มี scheduled sale, ราคาเศษ หรือ quantity management

ค่าเริ่มต้นปิดการเขียนไว้; ไม่เปลี่ยน decimals/manage_stock ของร้าน ไม่มีธุรกิจเพดานราคา; จำนวนเต็มรองรับสูงสุด 15 หลักตาม precision ของเส้นทางข้อมูลที่ใช้ ทุกการเปลี่ยนราคาต้องยืนยัน รวมล้างโปร ราคา 0 มีคำเตือนเพิ่มเติม
ราคาที่กรอกใช้บริบทภาษีของ WooCommerce เดิม ไม่บวก/ลบ VAT ให้เอง

- รักษา draft ในหน่วยความจำของแท็บเมื่อ refresh/error/conflict/login อีกแท็บ; ผลไม่แน่นอนให้ตรวจ operation แทนส่งซ้ำ
- Cookie+REST nonce+capability+object checks; private/no-store; soft request limits; write-stop ที่เซิร์ฟเวอร์

## บัญชีผู้ทดสอบ

Activation ให้เฉพาะ administrator: sdd_view_products, sdd_edit_products, sdd_manage_settings, sdd_view_audit ไม่เพิ่มให้ Shop Manager เอง
หากทดสอบ operator ให้ผู้ดูแลมอบ sdd_view_products และ sdd_edit_products แก่บัญชี WooCommerce ที่มีสิทธิ์แก้สินค้าตามหน้าที่อยู่แล้ว; ห้ามให้ settings เพียงเพื่อใช้ตาราง
รายการ publish ของผู้ไม่มี edit_others_products ถูกจำกัดเป็นสินค้าที่ตนเป็นเจ้าของ; draft/private ไม่อยู่ในตาราง

## ขั้นตอนตรวจรับ Local

- ค้นหา SKU/ID ที่ทราบและกรองแบรนด์ ตรวจว่าแท็กอื่นไม่ถูกใช้ค้นแบรนด์
- เปลี่ยนราคาปกติ → ยกเลิก confirmation แล้วตรวจว่าไม่เปลี่ยน; ทำใหม่และยืนยัน → ตรวจ WooCommerce หลังบ้าน
- ตั้งโปรต่ำกว่าราคาปกติ; ล้างโปร; ตรวจ 0 แยกจากไม่มีโปร; ป้อนเศษ/ลบ/exponent/comma ต้องถูกปฏิเสธ
- ลดราคาปกติจนเท่าหรือต่ำกว่าราคาโปร ต้องไม่ผ่านและต้องไม่ล้างโปรให้เอง
- เปิดสองแท็บแก้ช่องเดียวกันจากฐานเดียวกัน อีกแท็บต้อง conflict ไม่เขียนทับเงียบ ๆ
- ตัด network หลังส่งคำสั่ง → ค่าที่พิมพ์ต้องอยู่และใช้ตรวจผล operation; ไม่สร้างคำสั่งใหม่หากผลยัง unknown
- เปิด write-stop แล้วลองเขียน ต้องไม่ผ่าน; ตรวจบัญชีไม่มีสิทธิ์, nonce/session และสินค้าจัดการจำนวน/มีเวลาโปร/ราคาเศษ
- ตรวจ 1280×720, 1440×900, 1920×1080 และลองร่วมกับ third-party plugins ที่เปิดใน Local

## ข้อจำกัดที่ต้องรู้ก่อนทดสอบ

- มี bulk/rollback/feed/presence และประวัติรายสินค้าแล้ว; ยังไม่มี technical log viewer; variable parent อ่านอย่างเดียวแต่ขยายเพื่อแก้ลูกได้; bundle/type อื่นยังอ่านอย่างเดียว
- P1 ตรวจแยกช่อง: quantity ปิดเฉพาะ stock; ราคาเศษปิดเฉพาะราคา; future/active schedule แก้ราคาได้โดยคงวันเดิม; expired schedule แก้ราคาได้เมื่อยืนยันและคงวันเดิม โปรจะไม่กลับมาเริ่มใหม่
- ไม่มี persistent object cache support: เมื่อเปิด external object cache จะปิดการเขียน
- ไม่รับรอง external writers/third-party hooks ทั้งร้าน; hooks ที่ทำ implicit commit หรือ side effects นอก DB ไม่สามารถย้อนด้วย transaction นี้ได้
- Drift detection ไม่รับประกัน ABA จาก external writer ที่เปลี่ยนแล้วกลับก่อนตรวจ และไม่เดา actor ของการแก้ภายนอก
- Unknown/processing ที่ค้างไม่มีหน้าจอ reconcile ในรุ่น Local นี้; หยุดการเขียนและส่ง operation_id ให้ผู้ดูแลตรวจฐานข้อมูล ห้ามลบ record หรือสร้าง UUID ใหม่เพื่อหลบการตรวจ
- ไม่รองรับ multisite/custom product data stores/custom object ACL integration ในรุ่นนี้; ต้องตรวจแยกก่อนใช้
- Technical logger ส่งเฉพาะ error code/request UUID ไป WooCommerce logger พร้อม soft emission limit; health แสดงค่าการเปิดใช้ handler/retention/writeability/location ส่วน HTTP denial, rotation/source limits และ hard daily budget ยังไม่ยืนยัน; ไม่มี log viewer
- Automated database tests ใช้ CLI PHP 8.2.29 + WP 7.1.3 + WC 11.0.1 + MySQL 8.4.0 แบบแยก; web FPM, HTTP cache/CORS end-to-end, catalog load ~8500 และปลั๊กอินร้านทั้งหมด ยังไม่ได้รับรอง
- UI tests ใช้ WordPress React จริงกับ fixture API ไม่ใช่ WordPress HTTP end-to-end; ไม่เก็บ draft/nonce ใน localStorage และการปิดแท็บทำให้ draft หาย

## ปิดใช้งาน/อัปเกรด

Deactivate ไม่ลบสินค้า/audit/operations/capabilities ไม่มี uninstall routine ลบข้อมูลอัตโนมัติ
Schema version 5 ใช้ dbDelta สร้าง/ซ่อมแบบ idempotent; schema ไม่ครบหรือ table ไม่ใช่ InnoDB ปิด writer ไม่แกล้งเปิดสำเร็จ
อัปเกรดให้สำรองก่อนทุกครั้งและตรวจ migration report; รุ่นนี้เพิ่มดัชนี product_history และ status_updated จาก schema 4 โดยไม่แก้ข้อมูลราคา/การตั้งค่า
ไม่ใช้ ZIP นี้ deploy production จน integration/security/restore gates ครบ

## 0.1.3 Sale price dates

คอลัมน์ราคาโปรมีปฏิทิน **เริ่ม / สิ้นสุด** สำหรับ simple product ที่ราคาปกติ/ราคาโปรเป็นจำนวนเต็ม เลือกวันแล้วกด **บันทึก** และยืนยัน บันทึกสองช่องพร้อมกัน ไม่บันทึกเมื่อสลับช่องวัน
ใช้เขตเวลา WordPress ที่แสดง; วันที่เลือกใหม่เริ่ม00:00:00/สิ้นสุด23:59:59 ถ้าแก้เพียงช่องเดียว เวลาเต็มของอีกช่องคงเดิม วันสิ้นสุดต้องไม่ก่อนวันเริ่ม ตั้งวันต้องมีราคาโปรต่ำกว่าปกติ
วันเริ่ม/สิ้นสุดว่างได้ **ล้างวันโปร** ล้างทั้งคู่หลังบันทึกและยืนยัน โดยไม่ล้างราคาโปร จึงอาจทำให้โปรเริ่มทันที ราคาและสถานะอื่นคงเดิม
โปรอนาคต/ที่กำลังทำงานแก้ราคาได้พร้อมยืนยันและคงวันเดิม
เมื่อถึงวัน WooCommerce ใช้ scheduled sales/Action Scheduler เดิม ควรตรวจระบบ cron/queue ของ Local หากราคาไม่เปลี่ยนตามเวลา
ตรวจรับ: ตั้งวันเดียวกัน/อนาคตแล้วตรวจใน WooCommerce; ล้างวันแล้วตรวจ sale price ยังอยู่; สองแท็บแก้วันต้อง conflict ใช้สินค้าทดสอบก่อน

## P2 0.2.0 — Variations

- กด **+** หน้าสินค้าแม่เพื่อโหลดลูกทีละ20/50/100; ลูกแต่ละตัวแสดง ID/attributes/SKU ของตน ราคา/วันโปร/สถานะใช้ writer เดิมและยืนยันเหมือน simple แม่แสดงช่วงราคาปกติและจำนวนลูกแบบอ่านอย่างเดียว
- ค้น SKU/ID ของลูกแล้วพบแม่; ค่าเริ่มต้นแสดงลูกที่ตรงคำค้น/สถานะ กด **ดู variation ทั้งหมด** เพื่อดูนอกผลกรองโดยมีป้ายบอก; brand/category ใช้จากแม่ หมวดรวมลูกหลาน
- เรียงชื่อ/SKU/ราคาปกติจาก server ทั้งชุดก่อนแบ่งหน้า ราคาแม่ใช้ราคาปกติต่ำสุดของลูกที่เผยแพร่ ค่าไม่มีราคาอยู่ท้ายทั้งสองทิศ
- ลูกที่จัดการจำนวนเองหรือใช้จำนวนจากแม่ปิดเฉพาะ stock status ไม่เปลี่ยน quantity/manage_stock; ราคายังแก้ได้ตามนโยบาย
- หลังบันทึกลูก parent sync ใน transaction ภายใต้ล็อกแม่และลูก; refresh ตารางแม่โดยรักษา drafts; unknown ใช้ตรวจผลคำสั่งเดิม
- Checkbox เลือกได้เฉพาะ simple/ลูกที่แก้ได้และโหลดอยู่ แม่ไม่มี checkbox; ยุบแถว/เปลี่ยนหน้าเอาลูกที่ซ่อนออกจาก selection แต่ draft ยังอยู่ในแท็บนี้ ยังไม่มีปุ่ม bulk ใน P2

ตรวจรับ Local: ค้น child SKU/ID, ขยายแม่, เปลี่ยน regular/sale/date/status ของลูกทดสอบ, ตรวจ WooCommerce ทั้งลูกและช่วงราคาแม่; ลองสองแท็บ/stock จากแม่/กรองสถานะ/เรียงราคาข้ามหน้า; ส่ง feedback ก่อน P3


## 0.2.1 — โปรชั่วคราว

แอดมินเปิด **โปรชั่วคราว** ใต้ราคาโปรของ simple/variation เพื่อกรอกราคาจำนวนเต็มและวัน–เวลาเริ่ม/จบ (timezone WordPress) ตรวจราคาเดิม/ราคาใหม่/วันเวลาและยืนยัน ก่อนเริ่มคงโปรเดิม เมื่อเริ่มใช้โปรชั่วคราว เมื่อจบคืนทั้งราคาโปรและตารางเดิม หากตารางเดิมหมดอายุจะใช้ราคาปกติตาม WooCommerce

มีการแก้ราคา/วันโปรคั่นกลาง → **ต้องตรวจสอบ** หยุดคืนอัตโนมัติ ให้ตรวจราคาปัจจุบันแล้วกด **ปิดรายการตรวจสอบ** เพื่อคงราคาที่แก้เอง ยุติโปรที่ active จะคืนเดิมเฉพาะข้อมูลยังตรงและสิทธิ์ผู้สร้างครบ

ต้องมี cron ทำงาน Local หลับ/ไม่มี request/คิวล่าช้าทำให้เริ่มและคืนช้า เปิด write-stop หยุดทั้งเริ่มและคืน จึงต้องตรวจสถานะและรีเฟรชตารางหลังถึงเวลา Schema2เพิ่มตาราง snapshot แยก ไม่แก้สินค้าหรือ reset settings เดิม

ต้องยุติ/จบและตรวจโปรที่ค้างทั้งหมดก่อนปิดปลั๊กอินหรือ downgrade รุ่นเก่าไม่มี engine คืน snapshot ให้ ห้ามใช้ผล scratch tests แทนการตรวจรับเว็บร้านพร้อม third-party plugins และ cron จริง


## 0.2.9 — ตารางกระชับ / ขยายจัดการโปรใต้สินค้า

กด **จัดการโปร** เพื่อเปิดแผงเต็มความกว้างใต้สินค้าหรือ variation ที่เลือก เลือก **โปรชั่วคราว** (แอดมิน) หรือ **โปรตามช่วงเวลา** ราคาและ date/time picker อยู่ด้วยกัน พร้อมสรุปก่อนเริ่ม/ระหว่าง/หลังจบ ตัวกรองรองพับได้; ซ่อน checkbox ก่อนมี bulk

## 0.4.1 — Durable publication

เพิ่ม schema 3 แบบ additive สองตาราง สำหรับ publication sequence ที่แยกจาก audit ID พร้อม scoped GET/events และ cursor ผูกบัญชี/ชุดสินค้าอายุ 24 ชั่วโมง Publisher รันแยก connection ผ่าน heartbeat/cron ครั้งละไม่เกิน 200 เหตุการณ์ และลองใหม่เมื่อขัดข้อง หน้าตารางยังใช้ snapshots แบบเดิม External adapters/ABA และ whole-shop gates ยังเปิดอยู่ Rollback เป็น 0.4.0 ต้องหยุด cron/publisher คืนไฟล์และตรวจแล้วคืน schema option เป็น 2 โดยคงตารางใหม่ไว้

## 0.4.2 — External observations

Schema4 เพิ่ม outbox เก็บการแก้ published simple/variation ผ่าน metadata hooks และเพิ่ม revision แม้ราคา A→B→A โดย reducer ใต้ product lock ประมวลผลก่อน Writer ตรวจ baseline และผ่าน workspace POST/cron แบบ bounded ไม่ commit transaction แทนผู้แก้ภายนอก ไม่สร้าง actor ปลอม ไม่รวม external events ใน Recent หาก capture ล้มเหลวพยายาม latch warning ปิด plugin writes จนตรวจสอบ SQL ที่ข้าม hooks/unsupported cache/third-party plugins ยังไม่รับรอง Native cron ที่เปลี่ยนเฉพาะ derived _price ไม่สร้าง audit ปลอมของ sale price/dates; original values/dates retained by installed Woo version Whole-shop/performance/health-reset UI ยังเป็น gate ถัดไป

## P5 0.5.0: ตรวจระบบและประวัติรายสินค้า

หน้า ตั้งค่า เพิ่ม health สำหรับ schema/writer/cache/คิว/ตาราง cron และเปิดรายละเอียด event ของสินค้าจากแถวในแท็บ แก้ไขล่าสุด สำหรับผู้มีสิทธิ์ดูประวัติ ทั้งหมดเป็นการอ่านอย่างเดียว ไม่ retry/reset/reconcile คำสั่งอัตโนมัติ; cron เป็นเวลานัดหมาย ไม่ใช่หลักฐานทำงานสำเร็จ

หน้า health ไม่รับรอง production readiness การตรวจ log storage/retention, recovery/restore, PHP 8.3.31 FPM, cache/proxy และ third-party integration ยังต้องผ่าน P5 ขั้นถัดไป โปรดดูรายงาน p5-0.5.0-health-audit.md ใน source repository

## P5 0.5.1: ตรวจการตั้งค่า logger

หน้า health อ่านสถานะ WooCommerce logging, ประเภท handler, retention, writeability ของ log directory, ตำแหน่งเทียบ web root และ marker ป้องกัน directory โดยไม่คืน path และไม่เปลี่ยนค่าของ WooCommerce; health คง warning เพราะยังไม่ยืนยัน HTTP denial และยังไม่มี hard daily budget. ยังไม่มี log viewer หรือการลบ/retention แยกเฉพาะ plugin

## P5 0.5.3: จำกัดอายุ operation และ audit

มี cron รายวันลบ operation ที่ปิดแล้วและ event เก่ากว่า 90 วันเป็นชุดจำกัด โดยไม่ลบงาน unknown/pending/processing, event ที่ยังเป็น rollback target, field state หรือ revision ปัจจุบัน ตรวจผลและขอบเขต production ที่ยังต้องยืนยันได้ใน `docs/p5-0.5.3-release-readiness.md` ของ source repository

## 0.5.5 — จัดพื้นที่โปรชั่วคราวและล้างฟิลเตอร์

## 0.5.11 — เว้นระยะฟอร์มโปรชั่วคราว

เพิ่มช่องว่างรอบฟอร์ม/การ์ด/ปุ่ม และรวมเหตุผลราคา วันเดิม และเงื่อนไขคืนราคาให้อยู่แถวเดียวบนจอกว้าง พร้อมเรียงลงเมื่อจอแคบ

## 0.5.10 — จัด pill โปรโมชั่นกึ่งกลาง

จัด pill ทุกสถานะในคอลัมน์โปรโมชั่นไว้กึ่งกลางช่องอย่างชัดเจน รวมถึง “โปรเดิมหมดอายุ”

## 0.5.9 — จัดแนวคอลัมน์สรุป

ตัวเลขในคอลัมน์ราคาปกติและราคาโปรชิดขวาและเรียงหลักตรงกัน; คอลัมน์สต็อกและโปรโมชั่นจัดกึ่งกลาง ข้อความสรุปของสินค้าตัวแปรใช้แนวเดียวกับข้อมูลชนิดเดียวกัน และไม่มีราคาโปรใช้ขีดเหมือนแถวสินค้าอื่น

## 0.5.8 — สรุปแถวสินค้าตัวแปร

แถวสินค้าตัวแปรแสดงช่วงราคาปกติ จำนวนตัวเลือกที่มีราคาโปร และจำนวนตัวเลือกแยกตามสถานะสต็อก ข้อมูลเป็นสรุปอ่านอย่างเดียว; เปิด “ดูตัวเลือก” เพื่อแก้ค่าที่แถวของตัวเลือก

## 0.5.7 — แยกสถานะโปรโมชั่นและปุ่มจัดการ

คอลัมน์ “โปรโมชั่น” แสดงเฉพาะสถานะ และปุ่ม “จัดการโปร” อยู่ในคอลัมน์ “จัดการ” ของตัวเอง แผงโปรและแถวตัวเลือก variable ขยายครบ 7 คอลัมน์ เพิ่มการนำทางด้วยคีย์บอร์ด/โปรแกรมอ่านหน้าจอ และทำให้ตารางเลื่อนแนวนอนได้ รุ่นนี้ส่งเข้า Local ให้ผู้ใช้ตรวจ UI แล้ว

## 0.5.6 — หน้าตาตามภาพอ้างอิง

ปรับหัวหน้า แท็บ ค้นหา/ตัวกรอง ตารางสินค้า สถานะ และแผงโปรใต้สินค้าที่เลือกตามภาพที่อนุมัติ โดยคงการแก้ราคา/สต็อก การตั้งและคืนโปร ประวัติ การตรวจข้อขัดแย้ง การยืนยัน และสิทธิ์เดิมไว้ ภาพตัวอย่างใช้เพื่อกำหนดหน้าตา; ข้อมูลที่แสดงจริงดึงจากสินค้า WooCommerce.
